## P1-03 持久化任务队列、租约与心跳 ✅

- 状态机：queued → running → succeeded/failed(→queued 重试，上限 max_attempts)/cancelling → cancelled/needs_input → queued。
- 测试（`tests/test_queue.py`）：
  - 20 个任务全部成功，无丢失、无重复执行；
  - 3 个并发 Worker 共抢 20 任务：恰好 20 次领取、每任务恰好执行 1 次；
  - 模拟强杀：租约过期前**不**回收（防误判双重执行）；过期后回收重排，恰好再执行一次；
  - 重试上限：attempt 达 max_attempts 后落 failed；
  - 取消：running 任务经 cancelling → cancelled；
  - needs_input → resume(payload 补充) → succeeded；
  - 幂等键：同 key 二次入队返回已存在任务。
- 修复记录（真实性说明）：
  1. 初版 `claim_next` 在竞争失败时返回 None，导致并发 Worker 误判"队列已空"提前退出
     （复现：`sum(results)==11 != 20`）——已改为函数内重试，仅当无 queued 行才返回 None；
  2. `Worker.run` 增加 `exit_when_empty`/`idle_timeout`，避免测试线程在队列排空后无限轮询导致
     pytest 收尾挂起。
- 已知边界：SQLite 单写者，`busy_timeout=5000` 序列化并发写；租约回收基于 `lease_until` 过期 +
  心跳续租，满足 5.2"经核查后回收"（Worker 存活时心跳不断，不会被回收）。
